# What JSON Schema 2020-12 and Draft-07 mean beyond their keyword lists

> **A reader's report, not a finding of this repository.** Commissioned on 24 November
> 2026 for the plan `.agent/plans/active/model-design.md` (M1, the texts). It is one reader's
> account of the sources it names, kept whole so that the reading can be checked. The
> seat has not yet checked its claims against the sources; what the design takes from it
> is stated, with what was checked, in the notes that cite it.

I read all four specification texts end to end. Every quote below was checked mechanically against the text. Ten findings change the work (F1–F10); the biggest are:

- the computed 2020-12 keyword list misses four keywords of the default dialect;
- writing the Format-Assertion vocabulary conflicts with carrying unknown `format` values as annotations;
- Draft-07's `format` set and its cited standards differ from the 2020-12 ones the hand list uses.

## Findings that change the work

**F1. The computed 2020-12 keyword list misses four keywords of the default dialect.**

- `lib/tests-picture/rows/published-rows.ts` reads only the seven vocabulary meta-schemas.
- The live dialect meta-schema also defines `definitions`, `dependencies`, `$recursiveAnchor` and `$recursiveRef`, each with `deprecated: true`.
- Validation §5 mentions "two former keywords which are reserved for a transitional period" but does not name them.
- Validation Appendix A: under that meta-schema `definitions` SHOULD behave as `$defs`.
- Derived, not stated: no 2020-12 text gives semantics to `dependencies`, `$recursiveRef` or `$recursiveAnchor`. By Core §6.5 they are annotations in a 2020-12 document, so 2020-12 `dependencies` is not Draft-07 `dependencies`.
- The e2e test (`published-rows.e2e.test.ts`) asserts that `definitions` and `dependencies` are keywords "Draft 2020-12 replaced or removed". That claim holds for the vocabularies, not for the default dialect.

**F2. Format-Assertion has consequences the owner has to rule on.**

- SPEC-P-3 says the 2020-12 Castr writes "declares the format-assertion vocabulary".
- `$vocabulary` is read only in a meta-schema (Core §8.1.2). A document therefore declares vocabularies only through the meta-schema its `$schema` names. The official 2020-12 dialect meta-schema does not list format-assertion, so Castr would have to name a meta-schema that does.
- Under Format-Assertion, a validator "MUST fail upon encountering unknown formats" (Validation §7.2.3). "Unknown" is relative to each validator.
- The hand list carries an unlisted `format` value as an annotation, "never a refusal", and lists OpenAPI values such as `int32` and `password`. Writing those values under Format-Assertion makes conforming validators refuse the document.
- Validation §7.2.2 says the default meta-schema lists format-assertion as `false`. The live meta-schema does not list it at all.

**F3. Draft-07 defines a different `format` set and cites different standards.**

- Draft-07 defines no `duration` and no `uuid`; in Draft-07 they are unknown formats.
- `email` is RFC 5322 §3.4.1, where 2020-12 uses RFC 5321 §4.1.2.
- `hostname` is RFC 1034 §3.1, where 2020-12 uses RFC 1123 §2.1.
- FORMAT_ROWS cite "JSON Schema Validation 7.3.x" with the 2020-12 standards and name no draft.

**F4. Three hand-list notes need attention.**

- The `integer` row note, "A number asserted to be a safe integer", may describe the Zod check. No row states the source meaning, "any number with a zero fractional part".
- On `maxLength`, the `.ts` note says "Both count characters, not UTF-16 units". The report says Zod counts UTF-16 units. They disagree.
- The `.ts` note on `$ref` omits the report's "Keywords beside it apply too".

**F5. The Draft-07 `$ref` text is silent on `$id` and `definitions` beside it.**

- Draft-07 says "All other properties in a "$ref" object MUST be ignored."
- It does not say whether a `$id` (base URI) or `definitions` (reference targets) beside `$ref` still take effect.
- That root shape is common in generated Draft-07 documents.

**F6. The Relative JSON Pointer citation conflicts between the drafts.**

- Both drafts cite draft-handrews-relative-json-pointer-01. 2020-12 cites it as December 2020 with editors Luff, Andrews and Hutton; Draft-07 as November 2017 with Luff and Andrews.
- I did not settle the grammar from memory.

**F7. The anchor-name grammars differ.**

- 2020-12 `$anchor` and `$dynamicAnchor`: `[A-Za-z_][-A-Za-z0-9._]*`.
- Draft-07 fragment `$id`: `#[A-Za-z][-A-Za-z0-9_:.]*`.
- A colon has no 2020-12 counterpart, and a leading underscore has no Draft-07 counterpart.

**F8. `exclusiveMinimum` and `exclusiveMaximum` are numbers in both drafts.**

- The boolean form belongs to draft-04, which OpenAPI 3.0 uses, and is outside §6's JSON Schema drafts.

**F9. Two wordings mark where absence and an explicit default part.**

- 2020-12 Core uses "same assertion behavior" for the annotating applicators: `prefixItems`, `items`, `properties`, `patternProperties`, `additionalProperties` and both `unevaluated*`.
- "Same behavior" appears elsewhere: `dependentSchemas`, `propertyNames` and all of Validation.
- Core §7.3: an absent keyword never annotates, but an explicit default such as `additionalProperties: {}` does, and so feeds `unevaluated*`.

**F10. An absent `$schema` needs a profile rule.**

- In 2020-12, an absent `$schema` at the document root makes behaviour "implementation-defined".
- Draft-07 is silent.
- SPEC §6 forbids inferring a dialect, so a document without `$schema` needs a profile rule.

## Equivalence sets: one meaning, several spellings (the model holds one value)

Each set is marked **stated** (the text says so) or **derived**. Where it breaks is given.

1. **Tuple**
   - Draft-07 `items: [S…]` + `additionalItems: R` means the same as 2020-12 `prefixItems: [S…]` + `items: R`.
   - Stated: the Core §10.3.1.2 editor's note says "// When "prefixItems" is present, the behavior of "items" is // identical to the former "additionalItems" keyword.", and the change log agrees.
   - Breaks: the 2020-12 forms annotate, which `unevaluatedItems` reads; the Draft-07 forms do not.
2. **Uniform array**
   - Draft-07 `items: S` means the same as 2020-12 `items: S` with no `prefixItems`.
   - Draft-07 `additionalItems` beside schema-form or absent `items` is the same as no `additionalItems`.
   - Stated in Core §10.3.1.2's editor's note and Draft-07 §6.4.2.
3. **Dependencies**
   - Draft-07 `dependencies {k: S}` means 2020-12 `dependentSchemas {k: S}`.
   - Draft-07 `dependencies {k: [n…]}` means 2020-12 `dependentRequired {k: [n…]}`, which means `dependentSchemas {k: {required: [n…]}}`.
   - Stated in Validation Appendix A.
   - Derived: it also equals `if: {type: "object", required: [k]}, then: S`. The `type` guard is needed because `required` passes non-objects.
   - 2020-12 `dependencies` is NOT in this set (F1).
4. **Definitions**
   - Draft-07 `definitions` means 2020-12 `$defs`, and 2020-12 `definitions` under the default meta-schema (a SHOULD).
   - Stated in Validation Appendix A.
   - A definition is identified by its resource and name; `#/definitions/x` and `#/$defs/x` are two pointers to it.
5. **Plain-name anchor**
   - Draft-07 `$id: "#foo"` means 2020-12 `$anchor: "foo"`.
   - Stated in the 2020-12 Core change log.
   - Breaks: F7. A name with a colon, or one starting with `_`, has no counterpart.
6. **One schema, many URIs**
   - All of these name one target: the canonical `$id`; `$id` plus a pointer; an enclosing resource plus a longer pointer; an anchor URI; `$id` with or without an empty fragment.
   - Stated in 2020-12 Core §4.3.5, §8.2.1 and Appendix A, and Draft-07 §8.2.2 and §8.2.4.
7. **`const: x` and `enum: [x]`**
   - Stated in 2020-12; derived for Draft-07 from its identical equality.
8. **Numbers equal in value**
   - `1.0` and `1` are one value in every keyword value.
   - Stated in §4.2.1 of both drafts.
9. **Order**
   - Object key order is not meaning: stated in §4.2.2.
   - Order and duplicates in `type`, `enum` and `required` are not meaning: derived from membership semantics.
10. **Booleans**
    - `true` means `{}`, and `false` means `{"not": {}}`: stated.
    - `false` also means `{"not": true}`, and in 2020-12 `enum: []`: derived. The Draft-07 meta-schema forbids `enum: []`.
    - A schema with only unknown keywords is the same as `true` for assertions. In 2020-12 those keywords still annotate.
11. **Nullability**
    - `type: [T, "null"]`, `anyOf: [{type: T}, {type: "null"}]` and the same as `oneOf` (the types are disjoint) are one meaning: derived.
    - Siblings that apply only to one type stay outside: `{type: ["string","null"], maxLength: n}` admits `null` (Core §7.6.1 uses this example).
    - `enum` including `null` is a third spelling.
12. **Integer**
    - `type: "integer"` means `type: "number", multipleOf: 1`, and `type: ["integer","number"]` means `type: "number"`: derived from "zero fractional part".
13. **Absent keyword and its stated default, for assertions only**
    - Zero for `minLength`, `minItems` and `minProperties`.
    - `false` for `uniqueItems`, `deprecated`, `readOnly` and `writeOnly`.
    - `[]` for `required` and `prefixItems`.
    - 1 for `minContains`.
    - `{}` for `properties`, `patternProperties`, `dependentSchemas`, `dependentRequired` and `dependencies`.
    - The empty schema for `items`, `additionalItems`, `additionalProperties`, `propertyNames` and `unevaluated*`.
    - Breaks (Core §7.3, F9): an explicit annotating default marks locations evaluated for `unevaluated*`; absence never does.
14. **`$ref` with siblings**
    - 2020-12 `{$ref: X, K…}` means `{allOf: [{$ref: X}, {K…}]}` for assertions: derived from §8.2.3.1.
    - Draft-07 `{$ref: X, K…}` means `{$ref: X}`: stated. Draft-07 can only express the 2020-12 meaning through `allOf`.
    - Breaks when K depends on adjacency. `unevaluated*` inside an `allOf` branch no longer sees `$ref`'s annotations. `additionalProperties` and `properties`, `items` and `prefixItems`, `then`/`else` and `if`, and `*Contains` and `contains` all separate. Annotation schema paths change.
15. **`$dynamicRef` and `$ref`**
    - `$dynamicRef` whose target is not a dynamic anchor means `$ref`: stated.
    - It also means `$ref` when no outer resource in the dynamic scope defines that anchor: derived.
16. **`format` aliases**
    - `full-date` means `date`, and `full-time` means `time`, where implemented: stated in both drafts.
17. **Vocabulary declarations**
    - Format-Annotation plus Format-Assertion means Format-Assertion alone: stated in 2020-12 Validation §7.1.
18. **Annotations combined across schemas**
    - `readOnly`, `writeOnly` and `deprecated` combine by OR, `examples` concatenate, and duplicate `default` values collapse: stated.
19. **Bounds**
    - F8: the boolean form of `exclusiveMinimum` is not in scope.
    - Within one draft, `{minimum: a, exclusiveMinimum: b}` means the stricter single bound: derived.
20. **Embedded and linked resources**
    - They are the same meaning: stated in Core §4.3.5 and §9.2.1.
    - Bundling under `$defs` changes nothing when Appendix B.1's conditions hold.
