# Cloud-Autonomy Trust

## Outcome

The Practice operates in cloud sessions and scheduled Routines with the same
trustworthiness it earned in local interactive sessions: an autonomous seat's
claims about itself and its world are reliable enough that the owner's
attention is spent on genuine forks, not on catching relayed errors. The value
currency is **trust per unit of owner attention** — a landed slice the owner
must re-check is worth little; a landed slice the owner never has to think
about is the product. The system repays the investment over many years and
keeps evolving.

## The bet

The 2026-08-26 arming walk was the estate's first live traversal of the
account-side machinery, and it returned a split verdict that defines this
node's work:

- **Mechanical trust is earned.** Gates fired, the dry-run seat held
  read-only, byte-verification caught a real stored-prompt corruption, the
  kill-switch posture is honest.
- **Epistemic trust failed on first owner contact, everywhere tested.** The
  queued-decisions register: five of eight rows defective in premise, frame,
  or owner-legibility (one premise unsupported — a "published package" claim
  no measurement backed: the npm registry shows no current release). The notification channel: configured since
  2026-08-23, never actually delivered until the owner repaired the account
  config mid-walk. The model setting: recorded as set, first measured firing
  served a different model. The walking session itself reproduced the same
  failure class live by relaying register rows unverified.

The bet: the cure is not more machinery but **grounded cognition made
mandatory in the environment where no owner is watching** — cloud seats
carry the full discipline stack, and every loop-authored owner-facing surface
carries a verified-premise, owner-plain-language contract. Configuration is
never trusted as behaviour: only a live traversal proves an account-side
mechanism, and each mechanism's first traversal is treated as its real test.

We are deliberately **not** doing: more platform machinery ahead of need; a
parallel-workers design; per-session-type exceptions to Practice mechanisms
(one policy serves every medium — the medium is a parameter, not a new
category, per the owner's 2026-08-24 teaching).

## Success looks like

- A firing's self-report (completion summary, incident rows, register rows,
  evidence records) matches externally measured reality — the delta is the
  trust metric, observed at every attended or audited firing, starting with
  the first attended live firing (its purpose is the honesty probe, not just
  the write probe).
- Owner interventions per session trend toward genuine forks only; corrections
  of relayed error trend to zero because each one gets encoded structurally
  (rule, contract, runbook refinement) rather than re-taught.
- Every account-side mechanism (notifications, model binding, write binding,
  connector tools, trigger self-management) has a recorded first live
  traversal; no capability is written as fact ahead of one.
- This node does not claim: that the loop is yet trustworthy unattended (the
  first attended firing and its honesty probe are still ahead), or that the
  row contract has been exercised by a firing.
