# Every piece of unmerged work reaches main or is deleted

## Goal

Every commit, dirty file, stash entry and stray ref in this estate that is not on
`main` is either on `main` through a green-and-clean merged PR or deleted with its
reason recorded on `main`. When this plan completes: zero open PRs; `origin`
carries only `main`; this clone carries only `main`, one worktree, no stash and
no Codex checkpoint refs; and the delivery ledger, the correction plan and the
thread record say exactly that.

## Mechanism

Unmerged work is a set of deltas against `main`. Each delta gets one of two end
states, chosen by doctrine, never by convenience:

- **Merged.** A product-code delta lands only with its proof: a test that fails on
  unpatched `main` and passes with the cure, in the same PR, all gates green, one
  gate at a time, no check skipped, disabled, loosened or updated away. A
  documentation delta has one of two proofs by class: doctrine or claim text
  (vision, Practice records, API and behaviour prose, manifests, and records that
  retract or restate an owner ruling) lands with the owner's explicit approval;
  mechanical reference repair (links, indexes, dangling references) lands on the
  validator that proves it. Because owner, Claude and Codex all post to GitHub as
  one identity, no review, comment or merge event can attribute an approval; the
  approval record is the owner's own words quoted in the PR body under the heading
  `## Owner approval` with the date and the channel they arrived on (a terminal
  message, a PR comment the owner wrote, the comms log), mirrored in the ledger
  row. A ruling the owner has already given is quoted the same way. Every
  landing also passes the repository validators. The container branch is a
  reference for the cure; the cure matches current doctrine and adds no escape
  hatch.
- **Deleted.** A delta is deleted when its behaviour is already on `main` (exact
  evidence named), when it contradicts current doctrine (the clause named), when
  the record it copies lives in the Practice home (the path named), when no
  witness can be constructed for the gap it claims (the no-witness record below),
  or when it is generated output that regenerates. "Superseded" and "reference"
  are reasons for deletion, never states. The reason is written in the PR body or
  ledger row that records the deletion, so every deletion is visible to the owner
  at review.

There is no third state. A decision only the owner can make (doctrine text; a
removed option wanted back as a feature) is put to the owner in a PR; merge is
the yes, close is the no, and a closed PR's delta is deleted. A question the
owner has said is not theirs is answered by the agent with its verdict in the PR.

**The no-witness record.** When a claimed gap yields no doctrine-shaped failing
test, the branch delta is deleted, and the record carries the four contents the
correction plan's proof contract requires: the scope investigated, the reason no
witness exists, any counterevidence, and how the container's documentation or
Practice claims were treated. Failing to devise a test is not proof that the
claim is false, so the register row about `main` is either withdrawn with the
counterevidence that disproves it or carried into the defects phase named in
§Out of scope. That is a record about `main`, not a bucket for work.

A PR keeps the commits of its head reachable under `refs/pull/<n>/head` after its
branch is deleted, so deleting a PR's branch loses no history; branches without a
PR are judged on content before deletion.

Closing an inherited PR is a consequence: the todo that exhausts a container's
deltas closes the PR with a comment naming the landing PRs and the deletion
record, and deletes the branch and the local `refs/remotes/pr/<n>` ref. Nothing
closes ahead of its work. The closing todo for each open PR is in the inventory
below.

## Doctrine every todo works under

1. **TDD, red first.** For product code the failing test is written and run on
   unpatched `main` before the cure; the PR body carries a section headed
   `## Red run on unpatched main` with the failing output. A container's test
   file counts as the red test only when its assertion derives from doctrine, the
   format specification or an independent oracle (the TypeScript compiler, the
   installed Zod runtime, AJV, a second generation run), never from the
   container's own output; the probe table already flags #12's error-text
   assertions and #18's rename-entry assertions as candidate-derived, so those are
   rewritten.
2. **One landing per PR, one story per PR**, commits are TDD cycles (test, cure,
   refactor together, green at every commit). PDR-132 two-round budget; past the
   budget a finding gets a diff only if it would misdirect or lose work.
3. **Every gate, every time.** Pre-commit, pre-push and CI run in full;
   `pnpm check` before every PR opens; one gate at a time when diagnosing. No
   `eslint-disable`, `@ts-expect-error`, `as`, `any`, `!`, `Record<string,
unknown>`, `Object.*`, `Reflect.*` in a cure, even where `main` carries them.
   No baseline file, no per-file exemption, no scope carved to fit a violator.
4. **Snapshots and fixtures** change only where the old expectation is the
   defect; the snapshot diff is read line by line and the reading is in the PR
   body. Generated fixtures are regenerated by the generator in the PR whose cure
   changes their bytes, never hand-edited and never imported from a branch.
5. **IR is truth.** The IR carries the wire name and every authored keyword;
   writers render; a writer that cannot represent an IR feature fails fast with
   an actionable error; a writer never consults the source document.
6. **Deletion is recorded where the owner reads.** The PR body of the landing
   that keeps a container's other deltas lists each deleted delta and its reason;
   a container with nothing kept gets its deletion list in the ledger row of the
   next records commit. Branch deletion follows the record, never precedes it.
7. **Reviewers.** Every product PR: pre-execution `code-reviewer` on the planned
   cycle, then the gateway wave (`code-reviewer`, `test-reviewer`,
   `type-reviewer`) plus the family specialist (`zod-expert`, `openapi-expert`,
   `json-schema-expert`, `mcp-expert`; `security-expert` for W4-3). Every
   documentation PR: `docs-adr-expert` and `onboarding-expert`. The OCE
   `pr-lifecycle` and `proportionality` skills govern the PR itself.
8. **The hook policy is never bypassed.** `git stash drop` is blocked for agents:
   W4-3's drop is the owner's action after the content is on origin. `git
restore`, `git checkout --`, `git clean -f` and `git reset --hard` are blocked:
   a dirty worktree whose content is dispositioned deleted is removed with `git
worktree remove --force` after the record lands, never emptied file by file.
9. **Live claims and processes.** Before any worktree is removed, its path is
   checked against `active-claims.json` and against running processes (`lsof
+D <path>` or `ps` on the watcher); a worktree with a live claim or a running
   process is not removed until that is resolved (W4-5 resolves the one known
   case).
10. **Owner-decision PRs do not hold the plan.** W0-1, W1-13, W1-17, W2-1,
    W2-3, W2-4, W2-5, W2-8 and W4-3 carry doctrine-class content. Every owner
    decision is raised as a decision card (`AskUserQuestion` or the host's
    equivalent, one decision per card, recommendation first) at the moment it
    exists, and the blocked-on-owner alert goes to the owner's mobile channel at
    once (`owner-attention-at-action-moments`); the PR body carries the owner's
    quoted answer under `## Owner approval`. A ruling the owner has already
    given is applied, not re-asked. Every other todo continues meanwhile; W5-1
    waits for the answer, and the plan records the wait.
